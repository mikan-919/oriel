# 実行履歴

Relayは、実行権を取得したときに実行IDを発行し、実行開始・段階変更・検証結果・終了・実行権の解放・接続切断をSQLへ保存します。ブラウザーを開いていなくても保存し、端末やRelayの処理が再起動した後も取得できます。再実行は別の実行IDになります。

保存する検証結果には、検証したコミット、基準コミット、検証設定の識別子、完了数・総数・結果を含めます。設定の識別子はコマンド配列から作ったハッシュ（内容の識別に使う値）です。会話本文、WHAT/HOW本文、端末出力、検証コマンドの引数、認証情報は保存しません。停止理由は分類だけを記録し、原文の診断は端末のログで確認します。

Webの作業詳細で「実行履歴」を開くと取得します。取得中・失敗・履歴なしを表示し、「履歴を更新」で再取得します。保存済みの経過と画面で受信した進捗を合わせて表示します。履歴の検証成功は、その履歴に記載されたコミットの結果です。現在のPRの検証状態とは区別します。

履歴は所有者・リポジトリID・端末ID・作業番号で絞ります。別の利用者は取得できません。アカウントや対象の切替後に届いた応答は、切替先へ反映しません。外部サービスとの接続をやり直しても、同じ所有者と端末・リポジトリ・作業の保存履歴は残ります。

保持期間は90日、保存上限は所有者ごとに5000件、1回の取得上限は作業ごとの新しい200件です。保存時に期限と件数を超えた履歴を削除し、取得時も期限切れを除きます。上限で省略した場合は画面に表示します。同じ内容の連続通知は記録を増やさず、接続維持の応答だけでは保存しません。

接続切断と実行権の解放は成功や失敗を確定しません。デーモンから終了結果を受理した場合に限り、処理完了・失敗・停止を表示します。強制終了や通信障害で終了通知を受け取れなかった実行は結果未確定のまま残り、再開時の実行と区別します。「処理完了」はその実行の処理が終わったことを指し、PRのマージと作業全体の完了はワークフローの状態欄で確認します。
